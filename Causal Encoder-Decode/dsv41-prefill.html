关于「890 B/token」——这是引用值，不是本图推导： 该数字直接出自官方 model card 原文（"reduce the global KV cache footprint to 890 bytes per token — roughly 1/4 of DeepSeek-V4-Flash"）， 它指的是 global KV cache 的总占用（压缩主 KV + SWA 窗口 + 索引 K 等合计），不是单个 512 维主 KV 潜向量的字节数。

上表两条口径规则（务必先读）：
① engram 查表嵌入单独列在合计之外：它每个 token 只命中 24 行、不参与 GEMM，若计入则总数 769.51B， 与官方 552B 完全对不上 —— 说明官方"552B backbone"口径同样不含它。此前 v2 的表把它的参数量填进"激活"列 却又不计入合计，属自相矛盾，已修正为"—/按命中行数计"。
② 量化 scale 张量未计入：每个 fp8/fp4 Linear 都注册 scale，仅 routed experts 一项即 +16.99B。 但 engram 表的 scale 我却计入了（98.31B → 101.38B）。这是口径不一致，若统一计入，合计约 583.7B。
③ engram.wkv 计入合计与激活（它是真 Linear），与①的查表嵌入是两种东西 —— 同一阶段两种口径并存，故在此明写。
与官方口径的核对： ① 40 层 backbone（550.18B）+ embed/head（1.32B）= 551.5B，与官方 552B 吻合。 ② 现算 encoder 栈 20 层 = 7.89B（+embed/norm = 8.56B），官方记 prefill 8B；全 40 层 = 16.79B，官方记 decode 16B。 ③ 不含 engram 表的总计 566.75B 与 552B 的差额约 14.8B，主要是 DSpark MTP 14.32B。
